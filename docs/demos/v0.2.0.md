# v0.2.0 canonical demo — Playable World

This is the release QA path for the public browser build.

## Open the product

Public demo: `https://biandeshen.github.io/WorldBoxSR/`

Expected default path:
- Phaser renderer (no query string required);
- seed `45`;
- 24×24 world;
- 30 human founders;
- showcase warms deterministically to year 40 in chunks so the renderer becomes visible before warmup completes;
- eight explicit showcase grazers are spawned through the normal authoritative creature command path after warmup;
- selected speed is `60 days` per simulation step.

Do not change the seed or speed during the canonical release check unless the step explicitly asks for it.

## 5-second gate

As soon as the showcase is ready, a first-time viewer should be able to identify without reading project documentation:

- ocean/coast/land/vegetation structure;
- moving humans and grazers;
- named settlements, buildings, flags and territory;
- pause/speed/world-reset controls;
- the God Powers dock.

The world should be intentionally framed beside the inspector rather than clamped to the top-left of the browser.

## 30-second autonomous-world gate

Leave the foreground tab running at the default selected `60 days` speed after `showcase ready` appears.

Within the product's 30-second pacing budget, the world-event pulse must be able to surface a player-readable autonomous event derived from authoritative history: a settlement founding/abandonment or an aggregated human birth/death pulse.

This promise is executable, not estimated: `tests/showcase_30s_gate.test.js` parses the selected speed from `client/index.html` and `STEP_INTERVAL_MS` from `client/phaser_main.js`, then runs the same seed45 authoritative world and requires a readable event within that budget.

Browser background-tab throttling is not part of the foreground product gate.

## God-hand interaction gate

Use each power from the bottom dock (keyboard shortcuts `1`–`4` are optional):

1. **Human** — hover land and confirm the target tile is clear; ocean should show invalid targeting. Click land and confirm immediate spawn visual + short SFX.
2. **Grazer** — same targeting contract as Human; click land and confirm creature spawn visual + short SFX.
3. **Erase** — target a tile containing humans. Confirm an intentional erase effect/SFX and truthful entity removal.
4. **Lightning** — strike land. Confirm bolt/flash/ring feedback, SFX and authoritative vegetation/human consequences where applicable.

Audio is intentionally minimal in v0.2. There is **no ambient loop and no music**. Web Audio is created lazily only after player interaction; audio failure must never affect the simulation.

With the operating-system/browser reduced-motion preference enabled, strong power effects must use the reduced-flash profile and omit lightning camera shake.

## Inspection / navigation gate

- Drag the world to pan.
- Use the mouse wheel to zoom.
- Use **Alt-click or right-click** to inspect a human, grazer, settlement or tile.
- Confirm the inspector updates and a persistent world-space selection marker remains visible.
- For moving humans/grazers, the marker should follow the selected entity; if that entity disappears, the selection must clear rather than point at stale coordinates.
- Open **Chronicle** for detailed authoritative event history; the world-event pulse is only a compact summary.

## Legacy comparison decision

For v0.2 only, the old Canvas renderer remains available at:

`https://biandeshen.github.io/WorldBoxSR/?renderer=legacy`

Its purpose is A/B evidence and a regression escape hatch during the presentation migration. It is **not** the default product. v0.3 should retire the legacy renderer by default unless a concrete regression workflow still depends on it.

## Automated release verification

Before tagging:

```bash
npm test
npm run smoke
npm run pages:build
```

The authoritative CI runs these checks. Presentation-affecting changes must also pass the real Chromium `visual-qa` workflow, which serves the production `/WorldBoxSR/` base path and saves fixed 1440×900 Phaser/legacy screenshots plus DOM/runtime logs.

## Release question

After the automated gates are green, open the actual Pages URL and answer one product question:

> Does this feel like the beginning of a game worth watching and touching, rather than a developer visualization?

A yes closes the v0.2 product boundary. New ecology research, civilization breadth, editor/replay scope, broad asset migration and deeper audio belong to later versions.
