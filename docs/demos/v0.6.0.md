# v0.6.0 canonical demo — Living Ecology

This is the release QA path for the public browser build. It verifies the v0.6 promise: **I can watch animal populations and vegetation affect each other, and see predation change that living system.**

## Open the product

Public demo: `https://biandeshen.github.io/WorldBoxSR/play/`

Canonical release configuration:
- Phaser renderer;
- seed `45`;
- Mode **Living Ecology**;
- supported 24×24 world;
- ordinary deterministic simulation is the only ecology authority.

Do not change seed or ecology config during canonical release QA.

## 5-second Living Ecology gate

Choose **Living Ecology**, Reset, and wait for `showcase ready`.

A first-time viewer should be able to identify:
- the map as the primary product surface;
- many visible orange/brown Grazers;
- compact HUD species/resource cues rather than an analytics panel;
- `🐾 N` living Grazer count;
- `🌿 N%` current authoritative vegetation utilization;
- creature inspection through Alt-click/right-click;
- Chronicle remaining secondary to the world.

The canonical warmup lands at year 40. For exact automated release evidence the gate pauses before reset so Y40 does not drift.

Expected Y40 canonical authority:
- living Grazers: **116**;
- natural Grazer births: **156**;
- Wolves: **0**;
- vegetation utilization: **17.50%** (`🌿18%` rounded HUD);
- god creature spawns: **0**.

## Natural-fauna truth gate

Confirm Living Ecology is not the Sandbox manual-Grazer showcase:
- natural founders were created by the supported initializer rather than a God Power;
- `god.spawn_creature` is absent before explicit Wolf QA setup;
- Grazers have reproduced naturally;
- no rescue/reseed/population target is visible or expected.

The release does not promise every map size or seed uses this exact supported initializer.

## Vegetation pressure → recovery gate

The permanent headless release test freezes an earlier reference point and two browser-visible checkpoints:
- Y34: `136 Grazers · 34.31% vegetation · 150 births`;
- Y40 trough: `116 · 17.50% · 156 births`;
- Y50 recovery: `68 · 37.44% · 160 births`.

In the public browser at Y40:
1. pause if needed;
2. confirm `🐾116 · 🌿18%`;
3. visually note the dense Grazer population and relatively sparse vegetation;
4. set **Time → 1 year**;
5. Play until year 50, then Pause.

Expected Y50 release evidence:
- living Grazers: **68**;
- natural births: **160**;
- vegetation utilization: **37.44%** (`🌿37%` rounded HUD);
- Wolves: `0` before explicit setup;
- god creature spawns: `0`.

The Y50 map should visibly be greener and less Grazer-dense than Y40.

Truth language matters: this demonstrates an observed natural pressure/recovery phase while Grazer abundance falls through ordinary lifecycle. It does **not** prove equilibrium, carrying capacity, guaranteed future recovery or Wolf-caused recovery.

## Species inspection gate

Alt-click/right-click a visible Grazer.

Confirm Inspector identifies:
- `Grazer #id`;
- current behavior such as `fed` / `foraging` / starvation variant;
- age;
- health;
- hunger;
- current tile.

Inspection is presentation only and should not advance or mutate the paused world.

## Canonical Wolf setup

The release has no natural Wolf-founder policy. The automated release path uses exactly one existing hidden QA Wolf setup after the Y50 recovery checkpoint.

Frozen automated setup:
- tile `(0,8)`;
- tile is passable and clear at Y50;
- nearest living Grazer Chebyshev distance is `3`;
- spawned Wolf becomes **Wolf #171**.

This QA setup is not a new visible God Power and must not be interpreted as natural Wolf initialization.

For normal manual product inspection, you do not need to reproduce the hidden QA setup. The automated full Chromium gate is authoritative for this exact release path.

## Predation authority gate

After the one explicit Wolf setup, the automated browser:
1. sets **Time → 1 day**;
2. real-clicks Play;
3. observes Wolf #171 first move `(0,8) → (1,9)`;
4. authority records Wolf #171 predating **Grazer #110**;
5. a matching `creature.died(cause:'predation')` follows;
6. the prey disappears from current living authority;
7. successful feeding lowers Wolf hunger;
8. no second `god.spawn_creature` appears.

A Wolf may later starve if prey is unavailable. The release does not require eternal Wolf survival or stable coexistence.

## Predation readability gate

After the hunt, pause the world.

Confirm player-facing surfaces explain the recorded consequence:
- World Event Pulse: `Wolf #171 hunted Grazer #110`;
- **Recent** Chronicle contains the same readable hunt;
- opening the hunt gives a Causal Event Card;
- card detail records the hunt tile and hunger before→after;
- the dead Grazer Subject is shown unavailable rather than fabricated back into current state;
- the living Wolf Cause remains resolved and offers **Show on map**.

Highlights/Conflict/Rule policies from v0.5 are not redesigned for this release.

## Current Wolf gate

Use **Show on map** from the living Wolf Cause.

Confirm the Inspector reflects current authoritative Wolf state, including:
- `Wolf #171`;
- current behavior (after canonical feeding: `resting`);
- current age;
- health;
- hunger;
- current tile.

The release specifically fixed stale selected-creature display: Inspector must follow current movement/feeding state rather than keep the pre-hunt tile/hunger.

## Read-only authority gate

Once the post-hunt world is paused, the automated release gate fingerprints serialized authority and requires all of these to be read-only:
- switching to Recent;
- opening the predation Event Card;
- Show on map for the living Wolf Cause;

The fingerprint must remain byte-identical through those presentation/navigation actions.

## Save/load + repeatability gate

The headless canonical test runs the complete release path three ways:
1. uninterrupted;
2. duplicate;
3. snapshot at Y40, restore, continue to Y50 recovery and the same Wolf hunt.

All three must produce identical canonical facts and byte-identical final authoritative snapshots.

This proves the Y50 recovery and later predation are not artifacts of rebuilding the world or presentation state.

## Release question

After publication verification, the release boundary is:

> Can I open the supported ecology world, identify the species, see vegetation pressure and later recovery emerge from ordinary animal population change, watch a real Wolf→Grazer predation consequence, understand what happened from the game-facing surfaces, and trust that repeatability/save-load remain exact without a hidden survival controller?

A yes closes v0.6. No new ecology feature belongs in the release handoff.
