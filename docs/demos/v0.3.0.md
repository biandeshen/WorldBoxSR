# v0.3.0 canonical demo — Civilizations Rise

This is the release QA path for the public browser build. It verifies the v0.3 promise without turning the demo into a debug exercise.

## Open the product

Public demo: `https://biandeshen.github.io/WorldBoxSR/play/`

Expected default path:
- Phaser renderer;
- seed `45`;
- 24×24 world;
- 30 human founders;
- deterministic warmup to year 40;
- selected speed `60 days` per simulation step;
- simulation remains authoritative; all political presentation is projected from engine state/history.

Do not change the seed during the canonical release check.

## 5-second world gate

Once `showcase ready` appears, a first-time viewer should be able to identify:

- terrain/water/vegetation structure;
- living humans and grazers;
- multiple named settlements/political identities with flags/colors/territory;
- pause/speed/world-reset controls;
- the God Powers dock.

The product must still read first as a living god sandbox, not as a strategy dashboard.

## Civilization identity gate

Inspect at least two active settlements from different powers.

Confirm each can expose:
- settlement name and population;
- controlling polity name;
- capital status where applicable;
- a real human ruler or truthful vacancy;
- readable relation/war context where applicable.

Political color/territory on the map must match authoritative settlement→polity ownership.

## Chronicle gate

Open **Chronicle**.

The seed45 warmup should preserve a readable civilization story rather than only recent low-value life events or repeated ruler churn. The rendered history should include representative high-value transitions from the real seed45 history such as:

- rebellion;
- peace/war context;
- conquest;
- army/battle consequences.

Event labels should be human-readable story copy rather than raw names such as `settlement.conquered`.

Click an event and confirm the detail remains factual and tied to the recorded authoritative event. Presentation must not invent causes that are absent from history.

## Autonomous pulse gate

After the warmup cursor is established, let the world run.

New high-value political events may produce a compact world-event pulse. Old year-0–40 political history must **not** immediately replay as if it just occurred.

Ordinary god-power feedback may use the same toast surface, but must remain distinguishable as direct player-action feedback.

## Warband / political outcome gate

The reusable executable scenario in `client/presentation/civilization_gate.js` is the deterministic conflict proof for release QA. It uses real engine systems and requires:

1. at least two authoritative powers;
2. real human rulers;
3. a recorded war;
4. mobilized authoritative warbands;
5. at least one spatial engagement;
6. a political-map transition such as conquest or rebellion;
7. deterministic repeatability.

The default seed45 at year 40 independently satisfies the same semantic gate; it is not a presentation-only scripted story.

## God-hand regression gate

v0.3 must not regress the v0.2 interaction loop:

- Human and Grazer powers spawn only through authoritative commands and reject invalid land-only targets truthfully;
- Erase and Lightning produce immediate feedback plus authoritative consequences;
- pan, zoom, pause, speed and inspection remain usable;
- reduced-motion/reduced-flash behavior remains intact.

Civilization depth does not replace the god-sandbox loop.

## Automated release verification

Before tagging:

```bash
npm test
npm run smoke
npm run pages:build
npm run pages:check
```

Required release evidence:
- CI success;
- production Pages workflow success on `main`;
- Chromium `visual-qa` success on the production project-site base path;
- release workflow successfully creates tag `v0.3.0` and the GitHub release from `docs/releases/v0.3.0.md`.

## Release question

After automated gates are green, the release boundary is:

> Can I watch settlements become distinct powers, understand who rules them, see that conflict changed the political map, and recover that story from the world itself — while the product still feels like a god sandbox rather than a strategy dashboard?

A yes closes v0.3. More civilization depth is intentionally deferred; v0.4 returns the active development focus to the God Power Sandbox.
