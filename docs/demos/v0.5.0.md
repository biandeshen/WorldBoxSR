# v0.5.0 canonical demo — World Stories

This is the release QA path for the public browser build. It verifies the v0.5 promise: **this world has a history I can follow, revisit and remember.**

## Open the product

Public demo: `https://biandeshen.github.io/WorldBoxSR/play/`

Expected default path:
- Phaser renderer;
- seed `45`;
- 24×24 world;
- 30 human founders;
- deterministic warmup to the showcase state;
- authoritative simulation/commands remain the only world truth;
- Event Cards, story focus, Watchlist and Chronicle lenses are presentation/query state only.

Do not change the seed during canonical release QA.

## 5-second World Stories gate

Once `showcase ready` appears, a first-time viewer should be able to identify:

- the living map as the primary surface;
- a compact Chronicle rather than a raw event/debug log;
- the four story lenses **Highlights · Recent · Conflict · Rule**;
- event rows that can be opened for more detail;
- compact Focused Story / Watchlist surfaces only when the player chooses to use them.

The right-side story UI should remain subordinate to the world rather than turning the game into an analytics dashboard.

## Establish one real causal story

The automated canonical gate uses the already-shipped **Lightning** power to create a meaningful recorded political transition through ordinary gameplay. This is not a test-only event injection.

For manual QA:
1. pause the world;
2. choose **Lightning**;
3. strike a current polity ruler for whom normal succession is possible;
4. resume briefly until the ordinary ruler system records a successor;
5. pause again and open Chronicle.

The exact ids below are the fixed automated seed45 evidence for the release gate. Manual clicking/timing can create different ids, but the required relationships and UI behavior are the same.

Automated reference path:
- Lindenvale Dominion ruler: Human `#23`;
- Lightning event: `#172`;
- ruler death event: `#173`;
- succession event: `#178`;
- successor: Human `#29`;
- polity: `#3` Lindenvale Dominion.

From the moment the post-succession world is paused, all remaining steps are read-only story/navigation checks. The automated gate fingerprints the serialized world at this point and requires it to remain unchanged.

## Causal Event Card gate

Open the new ruler-succession event from **Highlights**.

Confirm the card presents readable player-facing information rather than raw JSON:
- headline naming the political transition;
- readable detail describing the successor/predecessor relationship;
- year plus event id/type provenance;
- a **Subject** section;
- a **Causes** section.

In the canonical automated run Event #178 reads:
- `Lindenvale Dominion has a new ruler`;
- `Human #29 succeeds Human #23 after death`.

The Subject is Lindenvale Dominion. Recorded Causes include the retained death Event #173 and current Human #29.

Confirm unresolved/expired references, if encountered elsewhere, are shown as unavailable instead of silently guessed.

## Cause drill-down gate

From the succession Event Card, open the retained death-event Cause.

Confirm:
- the existing Event Card changes to the selected cause;
- the cause remains readable with provenance;
- the world does not advance merely because an event was opened.

Canonical automated reference: succession Event #178 → death Event #173.

## Map navigation gate

Return to the succession Event Card and choose **Show on map** for a current map-capable explicit reference.

Confirm:
- the world camera/inspector navigates to the referenced current object or polity capital;
- this is the same ordinary map/inspector surface, not a second story map;
- the Event Card remains usable.

Canonical automated reference: polity #3 Lindenvale Dominion resolves through capital **Lindenvale**, with inspector `map focus 15,12`.

## Watchlist gate

Pin the meaningful succession event and one supported related entity.

Confirm:
- Watchlist reaches `2/6 pinned`;
- the two entries are clearly identifiable;
- Open / Show on map / Follow story paths remain available where applicable;
- ordinary Chronicle browsing does not remove the pins.

Canonical automated refs:
- `event:178`;
- `polity:3`.

Watchlist is same-tab/session player memory. Do not expect cloud or cross-device sync.

## Focused Story gate

From the related entity row, choose **Follow story**.

Confirm:
- a compact bounded trail appears;
- events are ordered oldest → newest;
- the trail is built from explicit retained history rather than inferred current associations;
- selecting a trail row opens the existing Event Card while focus stays active;
- the map remains the primary visual surface.

Canonical automated polity #3 trail:
`[122,123,124,125,127,128,130,131]`

The automated gate opens Event #123 from that trail.

## Chronicle lens round-trip gate

While the Event Card, Focused Story and two Watchlist pins are still present, click:

1. **Recent**;
2. **Conflict**;
3. **Rule**;
4. **Highlights**.

Confirm:
- each lens remains capped and player-readable;
- Recent is newest-first readable retained history;
- Conflict contains only explicit conflict-related story types;
- Rule contains only explicit polity/ruler-transition story types;
- the open Event Card remains open;
- Focused Story remains focused;
- Watchlist remains `2/6 pinned`;
- returning to Highlights restores the ordinary representative view.

Exact numeric ids are deterministic release evidence, not text the player must memorize.

## Truth / authority gate

The automated gate captures the serialized authoritative world immediately after real Lightning + normal succession, then verifies that all of these are read-only:
- opening Event Cards;
- following a retained cause;
- Show on map;
- Pin/Unpin presentation memory;
- Follow story / opening trail events;
- switching Chronicle lenses.

The final fingerprint must match the post-causality baseline byte-for-byte and the world must remain paused.

Manual QA should likewise observe that browsing history does not itself make time advance, create events, alter rulers, change territory or mutate the simulation.

## Bounded-history honesty gate

Because authoritative history is intentionally bounded, old event/entity refs can become unavailable.

Confirm the presentation:
- keeps the stable identity when possible;
- labels the ref unavailable truthfully;
- does not fabricate a replacement entity, motive or causal story.

An unavailable row is valid product behavior; invented certainty is not.

## Regression gates

v0.5 must preserve earlier playable capabilities:
- six God Powers from v0.4 remain usable;
- Meteor/Rain authoritative intervention + visual feedback remain intact;
- civilization/ruler/war/conquest systems from v0.3 remain truthful;
- pan, zoom, pause, speed, reset and inspection remain usable;
- save/load, deterministic simulation, CLI/Simulation Lab and Pages delivery remain intact;
- reduced-motion/reduced-flash behavior remains covered by regression tests.

## Release question

After automated gates are green, the release boundary is:

> Can I create or choose a meaningful recorded world event, understand what happened and why from recorded facts, navigate back to the involved world, preserve what I care about, follow a coherent bounded story and browse history without the story UI becoming a second source of truth?

A yes closes v0.5. Do not add another story feature during release handoff; the next product stage is **v0.6 Living Ecology**.
