# Sprint 010 — First endogenous ecology loop

Status: **completed** (#93 / #94)

## Goal

Add one minimal creature, the **grazer**, whose survival consumes renewable vegetation. Default worlds remain creature-free; grazers enter only through explicit god spawning in v0.

The delivered loop is:

`vegetation regrowth → grazer hunger/movement/eating → vegetation depletion → regrowth`

## Typed identity boundary

Creatures use an independent typed ID domain:

- `world.creatures`;
- `nextCreatureId`;
- history entity kind `creature`.

They do **not** consume human `nextEntityId` values. This is a critical determinism boundary: human IDs feed keyed-random behavior, so inserting animal IDs into that sequence would have created hidden human-history changes unrelated to ecology.

Spawn history uses `creatureIds`, not the human-oriented `entityIds` payload. `historyForCreature()` is typed separately from `historyForHuman()`, and current creature references resolve through `world.creatures`.

Numeric ID collisions across human/creature domains are therefore safe because historical references carry `entityKind`.

## Grazer v0 state

Each grazer stores:

- creature ID;
- `kind: creature`;
- `species: grazer`;
- x/y;
- ageDays / bornDay;
- hunger;
- health;
- alive / causeOfDeath.

No reproduction or social state exists.

## Behavior

Each tick:

1. age and hunger increase;
2. if hungry and current vegetation is edible, eat;
3. otherwise a hungry grazer moves one passable step toward the locally highest vegetation and then tries to eat;
4. a non-hungry grazer may take a keyed-random passive step;
5. starvation damages health; health can recover while well-fed;
6. health <= 0 records typed `creature.died` history and removes the creature from the living collection.

All movement choices use keyed randomness / stable ordering and consume **no sequential world RNG**.

Grazers do not consume human food, attack humans, join settlements, own territory, or reproduce.

## Spawn command

`spawn_creature` currently accepts only `species: grazer`.

- explicit in-bounds land tile;
- bounded count;
- all validation before command-ID allocation;
- deterministic creation with no RNG;
- `god.spawn_creature` records typed `creatureIds`.

This establishes a typed command shape, not a species registry/framework.

## Persistence / metrics / history

Snapshot schema advances to **v10** with:

- `creatures`;
- `nextCreatureId`;
- creature counters.

Save/load continuation with living/dead grazer trajectories is deterministic.

World summary reports:

- living creatures;
- living grazers;
- creature meals;
- creature deaths.

Typed creature history supports spawn and death inspection without leaking into human history.

## Human isolation result

A dedicated 20-year test runs two creature-free worlds with radically different grazer configuration values.

Because no creature exists, all of the following remain exactly equal:

- sequential RNG state;
- human IDs/state;
- food state;
- settlement/territory state;
- lineage/union state;
- human causal history;
- human counters.

This proves grazer configuration is inert until a grazer is explicitly spawned.

## Ecology density evidence

After core CI, a temporary default-parameter density study ran:

- seeds `1/4/9`;
- explicit densities `0 / 5 / 20` grazers;
- 24×24 worlds, no humans;
- 2 years;
- all grazers spawned at the initially vegetation-richest land tile.

For every seed, vegetation biomass was monotonic with grazing pressure:

`0 grazers biomass >= 5 grazers biomass >= 20 grazers biomass`.

All runs also preserved the sequential world RNG exactly.

The temporary probe was removed before final merge.

This is sufficient to establish that the default grazer parameters create a real, interpretable vegetation-consumption loop. It is **not** evidence that default animal populations or reproduction are ready.

## Client

The existing lightweight client now exposes:

- `Spawn grazer` in the god-tool selector;
- Shift-click count 10 for spawn tools;
- a minimal square grazer marker;
- creature selection cycling alongside humans/settlements/tiles;
- creature inspector with species/ID/age/health/hunger/position;
- typed creature selection history;
- vegetation amount in the tile inspector;
- grazer / creature meal / death metrics in the HUD.

No art pass or UI framework work was added.

## Quality result

Core ecology passed **179/179 tests + smoke** before the client phase. The final feature head adds client/typed-history contract coverage on top of that and passes GitHub CI.

## Non-goals preserved

- no reproduction;
- no predator/prey;
- no combat;
- no settlement/territory behavior;
- no human food consumption;
- no multi-species registry/framework;
- no AI behavior tree;
- no fire/season coupling;
- no default animal population.

## Handoff

The project now has its first endogenous world loop where an autonomous non-human actor makes vegetation matter without player intervention after spawn.

Do **not** immediately add animal reproduction. The next ecology decision should measure carrying pressure / survival across explicit grazer densities and test a proposed reproduction rule off by default before any self-sustaining animal population is allowed into normal worlds.
