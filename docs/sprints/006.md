# Sprint 006 — Make world history inspectable

Status: **completed** (#85 / #86)

## Goal

Turn the simulation's existing authoritative history into an inspectable **causal timeline** in the lightweight client without inventing new historical facts or simulation behavior.

## Why this sprint existed

Sprints 003–005 deliberately refused to script away rare emergent settlement failure:

- broad storage v0 was rejected;
- scarcity was measured rather than guessed;
- demographic stock/flow explained natural settlement extinction;
- only 3/100 post-social worlds show natural abandonment by year200, and the failure paths are coherent but heterogeneous.

The project principles require:

- **Emergence over scripting**;
- **Legible causality**;
- **History is a first-class output**.

The missing product capability was not another rescue rule; it was the ability to inspect what actually happened.

## Delivered

### 1. Pure history query layer

Deterministic helpers now support:

- newest/oldest event ordering with bounded slicing;
- stable event lookup by event ID;
- settlement history using only explicit settlement subject / `settlementId` / causal references;
- human history using explicit subject, entity, mother/father, cause references, and spawn `entityIds` where recorded;
- typed resolution of `world`, `event`, `entity`, and `command` references;
- explicit unresolved event IDs after bounded-history eviction;
- explicit unresolved command references because no authoritative command log exists;
- current-entity resolution without pretending a dead/missing entity is still present.

### 2. Truth-boundary tests

The query layer is covered by tests for:

- ordering/pagination;
- settlement/human filters;
- causal resolution;
- eviction/unresolved semantics;
- exact snapshot/RNG neutrality;
- parameter validation;
- the critical rule that **current settlement membership must never retroactively associate an old birth/death event with that settlement**.

### 3. Client timeline/event inspector

The existing zero-framework Canvas client now includes:

- world vs current-selection history scope;
- newest-first vs oldest-first ordering;
- a bounded list of retained events with stable IDs and simulation year;
- click-to-inspect structured event details;
- explicit subject and causal-reference resolution;
- explicit empty, unresolved, and evicted states;
- direct human/settlement history when the selected object has explicitly attributable events.

The current-state inspector remains separate from historical facts.

### 4. Client contract tests

Headless tests validate:

- the browser entry parses as JavaScript;
- the expected timeline DOM contract exists;
- history-view formatting and scope behavior remain deterministic;
- evicted causal references stay visible rather than disappearing.

## Truth boundary

Timeline v0 displays only facts the authoritative history actually contains.

In particular:

- a birth/death event does **not** become historically associated with a settlement merely because the human currently belongs to one;
- a missing/evicted parent event remains an unresolved stable reference;
- a missing/dead entity reference is not rendered as a current entity;
- demographic/scarcity research labels remain derived analysis, not authoritative event causes;
- no new event spam was added solely to make the timeline look richer.

## Quality result

Final clean CI for #86: **152/152 tests + smoke**.

The one intermediate failure was a client empty-state wording mismatch; the UI was changed to an actionable `select a human or settlement` prompt rather than weakening the test.

## Non-goals preserved

- no settlement rescue/persistence behavior;
- no LLM narration;
- no retroactive historical membership inference;
- no framework rewrite;
- no kingdom/war/diplomacy;
- no elaborate timeline search/virtualization before profiling proves need.

## Handoff

The client can now expose both current state and recorded causal history. The next increment should be chosen on value, not presentation novelty. Candidate directions remain:

- territory/ownership visualization as authoritative current-state legibility;
- behavior-neutral causal-history improvements if an important historical fact is currently missing;
- richer world/resource structure;
- or a new simulation primitive only when a clear causal hypothesis justifies it.

Do not jump from timeline v0 to generated narrative or civilization labels.
