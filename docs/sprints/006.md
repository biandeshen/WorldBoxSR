# Sprint 006 — Make world history inspectable

Status: **active** (#85)

## Goal

Turn the simulation's existing authoritative history into an inspectable **causal timeline** in the lightweight client.

The world now produces meaningful, heterogeneous histories — including founded and abandoned settlements, births/deaths, player commands, ancestry, and stable causal references — but the client mostly shows only present state. Sprint 006 closes that product gap without inventing new simulation behavior.

## Why now

Sprints 003–005 deliberately refused to script away rare emergent settlement failure:

- broad storage v0 was rejected;
- scarcity was measured rather than guessed;
- demographic stock/flow now explains natural settlement extinction;
- only 3/100 post-social worlds show natural abandonment by year200, and the failure paths are coherent but heterogeneous.

The project principles require:

- **Emergence over scripting**;
- **Legible causality**;
- **History is a first-class output**.

The next step should make those histories visible, not normalize them away.

## Execution order

1. **Pure history query layer**
   - deterministic world-event ordering/slicing;
   - stable event lookup;
   - direct human/settlement subject filtering;
   - explicit settlement-ID filtering only where the event really recorded it;
   - typed causal-reference inspection/resolution;
   - unresolved references stay visible after bounded-history eviction.

2. **Headless query tests**
   - ordering/pagination;
   - subject filters;
   - cause resolution;
   - eviction/unresolved behavior;
   - exact snapshot/RNG neutrality;
   - no fabricated historical settlement membership.

3. **Client timeline panel**
   - recent world events with year/day, ID, and readable type;
   - selected human/settlement directly attributable events;
   - click/select event for structured details;
   - causal references shown explicitly;
   - empty/unresolved states legible.

4. **Settlement history legibility**
   - founded/abandoned events immediately visible for selected settlements;
   - current state remains in the existing inspector;
   - do not synthesize an abandonment cause that authoritative history did not record.

5. **Client smoke/manual contract**
   - keep the current zero-framework client architecture;
   - no authority or mutation moves into the browser UI.

## Truth boundary

Timeline v0 displays only facts the authoritative history actually contains.

In particular:

- a birth/death event does **not** become historically associated with a settlement merely because the human currently belongs to one;
- a missing/evicted parent event remains an unresolved stable reference, not silently erased;
- demographic/scarcity research labels remain derived analysis, not authoritative event causes.

This boundary is essential for future explainability: the UI must distinguish recorded fact from later interpretation.

## Non-goals

- no settlement rescue/persistence behavior;
- no new event spam solely for visual richness;
- no LLM narration;
- no retroactive historical membership inference;
- no framework rewrite;
- no kingdom/war/diplomacy;
- no elaborate timeline search/virtualization before profiling proves need.

## Quality gates

- all query transforms deterministic and pure;
- exact snapshot/RNG neutrality;
- history bounding semantics preserved;
- no fabricated associations in tests;
- client remains usable with empty history and evicted references;
- existing simulation/smoke tests stay green.

## Handoff

After timeline v0, the next client/world-observation decision can compare:

- territory/ownership visualization;
- richer settlement current-state context;
- selective derived explainability summaries;
- or a new simulation primitive if evidence supports one.

Do not jump directly from the timeline to generated narrative or civilization systems.
