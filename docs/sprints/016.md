# Sprint 016 — Promote grazer partner encounter radius 3

Status: **completed** (#107)

## Goal

Promote only the partner-search geometry proven by Sprint 015 from Chebyshev radius 1 to radius 3.

## Runtime change

Authoritative grazer reproduction now uses a private `REPRODUCTION_PARTNER_RADIUS = 3` constant when selecting an eligible second parent.

Everything else remains unchanged:

- each parent's local vegetation test still uses radius 1;
- birth chance and default-zero behavior;
- one-year maturity;
- health >= 0.95;
- hunger <= existing grazer hungry threshold;
- one-year successful-birth cooldown;
- stable deterministic pair ordering;
- keyed pair/day randomness;
- one newborn on parent A's tile;
- typed birth history and counters;
- daily ordering;
- snapshot schema v11;
- default worlds contain zero creatures.

No public interaction-radius config/framework is introduced.

## Verified gates

The implementation suite proves:

- an otherwise eligible pair at Chebyshev distance 3 creates exactly one birth;
- an otherwise eligible pair at distance 4 cannot reproduce;
- the generic missing-partner rejection now means no eligible partner exists within radius 3;
- sequential `world.rng` remains unchanged;
- default-off behavior remains inert;
- enabled save/load continuation remains exact without a schema change;
- the existing multi-seed 10-year reproduction regression still grows low density, keeps overloaded populations bounded, and preserves the low-vegetation carrying-pressure regime;
- full normal CI and smoke pass.

## Decision

Radius 3 is accepted as the authoritative grazer reproduction partner-search distance. It is a private mechanic constant, not a public interaction system.

The local vegetation condition deliberately remains radius 1, so wider encounter opportunity cannot bypass resource locality.

## Guardrails

No lifespan/senescence, mate bond, sex, genealogy, gestation, migration, population target, predators, species framework, human coupling, or snapshot change was introduced.

## Handoff

Natural turnover can now be re-researched against the corrected radius-3 encounter geometry. Do not assume any Sprint 014 lifespan band is valid; re-run the lifespan gate because changing encounter geometry changes replacement dynamics.
