# Sprint 007 — First causal god intervention

Status: **completed** (#87 / #88)

## Goal

Add one minimal destructive god action, `erase`, proving player intervention can change authoritative simulation state while preserving deterministic lifecycle bookkeeping and causal history.

This sprint deliberately did **not** create a generic powers framework, combat, disasters, or civilization systems.

## Why this sprint existed

Sprint 006 made authoritative history inspectable, but the product principle **God, not micromanager** was still represented only by `spawn_human`.

`erase` was chosen as the smallest opposite intervention because it crosses several important seams at once:

- command validation and deterministic IDs;
- human death bookkeeping;
- parental-union mortality bookkeeping;
- bounded causal history;
- settlement membership/lifecycle eventual consistency;
- client tool selection without moving authority into the browser.

## Delivered semantics

`erase` targets one world tile and removes all currently living humans on that tile in stable human-ID order.

It does **not** directly erase:

- settlements;
- territory;
- lineages;
- parental-union history;
- terrain;
- food.

An emptied settlement updates and may abandon only through its existing authoritative settlement cadence, exactly like natural human death. The client does not force an off-cadence membership refresh merely to make current-state numbers look immediate.

Empty-tile erase is a valid no-op intervention: it still records an accepted `god.erase` action with an empty target list. Erase consumes no RNG.

## Shared death lifecycle

The old private death mutation inside `systems/humans.js` was extracted to `model/human_lifecycle.js` as a reusable authoritative lifecycle helper.

Both natural old-age/starvation death and god erase now use the same path for:

- `alive = false`;
- `causeOfDeath`;
- death counter;
- `human.died` event;
- parental-union first-partner-death bookkeeping.

Entity-collection cleanup remains caller-owned so the regular tick system and synchronous god command preserve their existing timing semantics.

Natural death event shape was regression-tested: old-age/starvation death does not gain a synthetic causal reference merely because god erase supports one.

## Causal event chain

Accepted erase produces:

1. stable command ID after coordinate validation;
2. one `god.erase` world event containing tile, target count, stable target human IDs, and a command cause;
3. one `human.died` event per target with cause `erased` and a causal `eventRef` to the preceding `god.erase` event;
4. normal parental-union mortality history where applicable.

The Sprint 006 history inspector can therefore resolve:

`god.erase → human.died`

while the original command reference remains a stable unresolved command ID because no authoritative command log exists.

## Command invariant correction

While implementing erase, an existing inconsistency was found in `spawn_human`: an impassable-tile spawn could allocate a command ID before `createHuman` rejected the tile.

Spawn now validates tile passability before command-ID allocation. Rejected commands therefore no longer perturb deterministic command identity, matching the pre-existing command-layer invariant and comments. Valid spawn behavior remains unchanged.

## Client

The zero-framework Canvas client now has a minimal god-tool selector:

- **Spawn human** — default behavior; Shift-click still spawns 10;
- **Erase humans** — primary click erases humans on the clicked tile; Shift has no special erase meaning.

Right-click / Alt-click / touch inspection, pan, zoom, current-state inspector, and causal timeline behavior remain unchanged.

If an inspected human is erased, current entity resolution can disappear while the stable historical ID and death history remain queryable, preserving the current-state/history distinction.

## Tests and quality result

Final feature head passed **160/160 tests + smoke**.

Dedicated coverage includes:

- exact-tile targeting and stable target order;
- death count / `causeOfDeath`;
- RNG neutrality;
- resolvable `god.erase → human.died` history;
- parental-union mortality bookkeeping;
- no direct off-cadence settlement mutation;
- empty-tile erase;
- invalid-coordinate command-ID neutrality;
- rejected impassable spawn command-ID neutrality;
- save/load continuation after erase;
- legacy natural old-age death event shape;
- browser parse and god-tool DOM/entry contract.

## Non-goals preserved

- no radius erase;
- no erase-settlement command;
- no lightning/meteor/plague yet;
- no health/damage framework;
- no generic powers registry;
- no terrain destruction;
- no new settlement rescue/persistence logic;
- no kingdom/war/diplomacy.

## Handoff

The project now has a clean intervention seam:

`player command → authoritative god event → shared lifecycle mutation → social bookkeeping → inspectable history`.

Do **not** generalize a powers framework merely because spawn and erase now exist. A future intervention should first be justified on its own mechanics; only a second genuinely different power that demonstrates repeated infrastructure should trigger abstraction.
