# Sprint 007 — First causal god intervention

Status: **planned**

## Goal

Add one minimal destructive god action, `erase`, that proves player intervention can change authoritative simulation state while preserving deterministic lifecycle bookkeeping and causal history.

This sprint is not a generic powers framework and does not add combat, disasters, or civilization systems.

## Why now

Sprint 006 made authoritative history inspectable. The product principle **God, not micromanager** is still underrepresented: the only player intervention is `spawn_human`.

The smallest high-value next step is therefore a second command with the opposite effect. `erase` exercises several important seams at once:

- command validation and deterministic IDs;
- human death bookkeeping;
- parental-union mortality bookkeeping;
- bounded causal history;
- settlement membership/lifecycle eventual consistency;
- client tool selection without moving authority into the browser.

## Semantics

`erase` targets one world tile and removes all currently living humans on that tile.

It does **not** directly erase:

- settlements;
- territory;
- lineages;
- parental-union history;
- terrain or food.

An emptied settlement must update/abandon only through its existing authoritative settlement cadence.

## Causal event chain

1. accepted command receives a stable command ID;
2. one `god.erase` world event records tile and stable target human IDs, caused by that command;
3. each target dies through the shared human-death lifecycle with cause `erased` and a cause reference to the prior `god.erase` event;
4. existing parental-union first-partner-death bookkeeping runs normally;
5. dead humans are removed from the current entity collection immediately;
6. historical entity IDs remain queryable through the timeline even though the entity is no longer current.

Empty-tile erase is a valid no-op intervention: it still records the accepted god action with an empty target list. No RNG is consumed.

## Architecture

Extract the existing death mutation from `systems/humans.js` into a reusable model/lifecycle helper rather than making core commands depend on a simulation system.

Natural old-age/starvation deaths must preserve existing event/counter semantics exactly.

## Client

Add a minimal tool selector to the existing Canvas client:

- Spawn human (existing default behavior);
- Erase humans.

Primary click applies the selected tool. Existing right-click/alternate selection remains unchanged. Shift-count behavior remains spawn-only.

## Tests

- natural death lifecycle remains behavior-equivalent;
- erase removes exactly the living humans on the target tile in stable ID order;
- death counter / `causeOfDeath` / parental-union mortality stay correct;
- `god.erase → human.died` causal chain resolves in history queries;
- empty-tile erase is deterministic and consumes no RNG;
- invalid coordinates do not consume a command ID;
- settlement is not directly deleted by erase;
- save/load after intervention remains deterministic;
- client tool DOM/parse contract remains headless-testable;
- existing simulation and smoke tests remain green.

## Non-goals

- no radius erase;
- no erase-settlement command;
- no lightning/meteor/plague yet;
- no health/damage framework;
- no generic powers registry;
- no terrain destruction;
- no new settlement rescue/persistence logic;
- no kingdom/war/diplomacy.

## Handoff

If this command proves the intervention/lifecycle/history seam clean, future powers can reuse the same causal command/event contract. Do not generalize the framework before a second genuinely different power requires it.
