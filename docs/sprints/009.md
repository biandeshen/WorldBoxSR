# Sprint 009 — Lightning as a vegetation disturbance

Status: **completed** (#91 / #92)

## Goal

Add one deterministic exact-tile `lightning` intervention connecting the Sprint 007 god-action/lifecycle seam to the Sprint 008 vegetation substrate.

The delivered loop is intentionally small:

`lightning → local human death + vegetation reset → deterministic vegetation recovery`

## Delivered semantics

For any in-bounds tile, lightning:

- captures vegetation before strike;
- collects living humans on the exact tile in stable ID order;
- records one `god.lightning` event with command cause, tile, target IDs, and vegetation before/after;
- sets tile vegetation to zero;
- kills targets through the shared human lifecycle with cause `lightning` and a causal reference to the god event;
- removes dead humans from current entities;
- consumes no RNG.

Food, food capacity, terrain, passability, biome, territory ownership, and settlement lifecycle are untouched.

Ocean lightning is an accepted explicit zero-target / zero-biomass intervention event.

## Recovery

No burning or fire state exists. Existing deterministic vegetation regeneration is the recovery mechanism.

Tests verify a struck land tile begins regrowing on the next tick and eventually returns to vegetation capacity.

## Architecture result

`erase` and `lightning` share only two private exact-tile helpers inside `commands.js`:

- living-human collection in stable ID order;
- shared kill-loop cleanup.

No powers registry, damage abstraction, or generic effect framework was introduced.

## Client

The existing tool selector now exposes:

- Spawn human;
- Erase humans;
- Lightning.

Primary click applies the selected tool. Shift remains spawn-only. Right-click / Alt-click / touch inspection remains unchanged.

## Quality result

Final feature CI: **172/172 tests + smoke**.

Dedicated lightning coverage verifies:

- exact vegetation reset / exact human targets;
- food, terrain, ownership, and RNG invariance;
- `god.lightning → human.died` causal resolution;
- parental-union mortality bookkeeping;
- no off-cadence settlement mutation;
- deterministic vegetation recovery;
- ocean accepted no-op semantics;
- invalid-coordinate command-ID neutrality;
- deterministic save/load continuation;
- client parse and tool-selection contract;
- all existing long-run regressions including seed45 remain green when lightning is never invoked.

## Non-goals preserved

- no wildfire spread;
- no burning tile state;
- no damage/health framework;
- no radius/AOE;
- no terrain or food destruction;
- no meteor/plague;
- no generic power registry.

## Handoff

Lightning proves an environmental disturbance/recovery loop without additional framework machinery. Do **not** infer that wildfire is automatically next.

The next higher-value direction should preferably be an endogenous ecology loop—such as one minimal vegetation-consuming creature—because that would make vegetation matter without player intervention and would also exercise the still-open generalized creature-spawn backlog.
