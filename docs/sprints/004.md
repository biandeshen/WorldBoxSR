# Sprint 004 — Measure settlement scarcity before buffering it

Status: **active** (#81)

## Goal

Measure **settlement-level scarcity episodes** in the unmodified baseline simulation before designing any storage v1 or other growth mechanic.

The sprint is derived-only. It changes no world behavior.

## Why now

Sprint 003 showed that a broad local-meal storage fallback can be mechanically correct yet causally wrong. In seed98 it indirectly rescued resource-rich Pineford (#5) before Pineford itself used any stored food.

That result means the model must distinguish genuine settlement resource shortage from local access/path failure before another buffer is justified.

## Observation model

At a fixed research cadence, derive for every active settlement:

### Territorial resource state

- population;
- owned passable cells;
- current territorial food and food capacity;
- food remaining fraction;
- food per member and capacity per member;
- territorial meal equivalents = `territorialFood / foodPerMeal`;
- territorial meal coverage per member = `territorialFood / (population * foodPerMeal)`.

Report a transparent **one-meal territorial shortage** when total owned food is less than one existing meal unit per current member. Keep the continuous coverage metric alongside the flag.

### Local meal-path state

For current settlement members:

- hungry members using the existing `hungryThreshold`;
- hungry members whose current tile has less than the existing edible minimum (0.2) and whose one-step passable neighbors all also have less than 0.2;
- blocked-hungry share.

Report **access mismatch** separately when local blockage exists while territorial meal coverage is at least 1.

## Episode tracking

Track consecutive sampled periods independently for:

1. one-meal territorial shortage;
2. any local meal-path blockage;
3. access mismatch.

For each completed or active episode retain bounded aggregate facts only:

- settlement ID;
- start/end day and observed duration;
- samples observed;
- population at start and end/current;
- minimum territorial meal coverage;
- maximum blocked-hungry share;
- whether abandonment later occurs in the observed run.

No raw daily trajectory storage.

## Sentinel

Seed98 Pineford (#5) is mandatory:

- year100: population 11, ~96% food remaining;
- year120/140/160: population 8/7/3;
- abandoned around day 63,630.

Determine whether this collapse contains:

- territorial shortage;
- access mismatch;
- neither;
- or a transition between categories.

This result is required before any future storage design.

## Baseline

Start with seeds `1/4/9/45/80/98`, 24×24, 30 founders, 200 years if runtime remains acceptable.

Compare:

- prevalence and duration of territorial-shortage episodes;
- prevalence and duration of local-blockage episodes;
- fraction of blockage occurring as access mismatch;
- episode burden in settlements that later shrink/abandon versus those that remain active;
- seed45 and seed98 separately from the center.

## Decision gate

A storage v1 is worth designing only if recurrent scarcity episodes are:

- genuinely settlement-local rather than merely path/access failures;
- temporally persistent enough that buffering has a plausible role;
- associated with later shrinkage/starvation/abandonment in more than one hand-picked world;
- detectable using transparent settlement-local state without broad coupling.

If local blockage mostly occurs while territory is abundant, investigate access/membership/movement structure instead of storage.

If Pineford declines without either resource shortage or meaningful access mismatch, treat its failure as primarily demographic/social rather than economic.

## Non-goals

- no storage runtime;
- no food production bonus;
- no jobs/buildings/trade/tax/currency;
- no movement or eating change;
- no settlement membership change;
- no household/private inventory;
- no kingdoms/war;
- no client polish unless needed to inspect research output.

## Quality gates

- exact snapshot/RNG neutrality;
- tracker remains outside authoritative world state;
- bounded memory and no raw daily trajectories;
- existing meal/hunger semantics reused instead of outcome-tuned thresholds;
- deterministic artificial-world tests for each scarcity category and episode transition;
- temporary expensive probes removed before merge;
- negative results recorded rather than parameter-tuned away.
