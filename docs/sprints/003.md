# Sprint 003 — Settlements buffer scarcity

Status: **completed — runtime mechanism rejected** (#79 / #80)

## Goal

Test whether a **small deterministic shared food store** lets settlements buffer short local shortages without turning food into a universal survival bonus or flattening world diversity.

This was a controlled causal experiment, not the start of a general economy system.

## Mechanism tested

The prototype was explicitly opt-in and mechanically narrow:

- capacity: 8 food units per settlement;
- territorial reserve: keep 85% of each owned tile's food capacity on-map;
- deposit cadence: existing 30-day settlement update;
- transfer: at most 25% of available surplus per cadence;
- deposits removed real food from owned territory and respected hard capacity;
- storage could be used only after the existing current-tile → one-step food-search → destination-eat path failed;
- active current members only;
- no production multiplier, movement preference, jobs, buildings, trade, household inventory, or extra RNG.

The disabled/default path preserved legacy simulation behavior and the seed45 regression.

## Evidence

### 100-year A/B

Seeds 1/4/9/45/80/98 showed that the mechanism was selective rather than a universal buff:

- seed1: 306 → 306, 0 store meals;
- seed4: 159 → 159, 0;
- seed9: 207 → 224, 1,611;
- seed45: 35 → 35, 0;
- seed80: 112 → 112, 0;
- seed98: 431 → 438, 379.

### 200-year A/B

- seed1: 662 → 667;
- seed4: 805 → 818;
- seed9: 609 → 630;
- seed45: 128 → 128;
- seed80: 871 → 857;
- seed98: 404 → 452.

The six-seed population center moved only modestly, so the stop condition was **not** broad population explosion. Seed45 also remained unchanged.

## Hard-guard failure — seed98

The critical failure was structural: seed98 changed from **6 active + 1 abandoned settlement** to **7 active + 0 abandoned**.

A targeted settlement-level audit confirmed that the rescued settlement was exactly **Pineford (#5)**, the known resource-rich demographic counterexample from the earlier resource study.

Baseline Pineford:

- year100: population 11, food remaining ~96.06%;
- year120: population 8, ~97.81%;
- year140: population 7, ~98.18%;
- year160: population 3, ~99.37%;
- abandoned around day 63,630.

With storage enabled:

- year100: population 16, store full at 8, **0 withdrawals / 0 store meals**;
- year120: population 29, store still full at 8, **0 withdrawals / 0 store meals**;
- year140: population 52; only then did Pineford consume ~8 food / 13 store meals;
- year200: population 48 and still active.

The rescue therefore began **before Pineford used storage at all**. Storage use elsewhere changed global demographic/spatial history and indirectly repopulated an already food-rich settlement.

## Decision

**Reject shared-food-storage v0.**

The implementation was mechanically correct, but its trigger — every individual's local meal-path failure — was too broad to support a clean settlement-level scarcity interpretation. Parameter-searching capacity/reserve/deposit after this result would risk fitting a fragile magic window rather than improving causal structure.

All storage runtime hooks, modules, tests, and temporary probes were removed before #80 merged. Main contains only the negative experiment report.

## What we learned

The project currently conflates at least two different phenomena:

1. **true settlement-level resource scarcity**;
2. **local access/path failure while broader settlement territory still has food**.

A shared store responds to both and therefore creates world-level coupling that can alter unrelated settlement survival.

## Handoff

Sprint 004 measures those phenomena directly, derived-only, before any storage v1 is considered.
