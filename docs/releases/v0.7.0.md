# WorldBoxSR v0.7.0 — Scenario Builder & Sharing

v0.7.0 turns WorldBoxSR’s deterministic startup and command architecture into a player-facing creation loop:

> **I can assemble a small world setup, share/import its compact Scenario Recipe, reopen exactly the same authoritative start, then Run, Replay or Fork a different history.**

This release is intentionally **not** a full world editor. A Scenario Recipe is a small versioned startup input, not a live-world snapshot and not a second simulation authority.

## Shipped

### Versioned Scenario Recipe v1

The release has one strict, deterministic Recipe contract:

```json
{
  "kind": "worldboxsr-scenario",
  "version": 1,
  "name": "My scenario",
  "base": { "seed": 45, "preset": "sandbox" },
  "setup": [
    { "type": "spawn_human", "x": 8, "y": 8, "count": 1 },
    { "type": "spawn_creature", "species": "grazer", "x": 9, "y": 8, "count": 1 }
  ]
}
```

Frozen v0.7 scope:
- base = the existing 24×24, 40-year showcase-ready `Sandbox | Living Ecology` startup;
- setup = ordered Human, Grazer and Wolf placement only;
- max 32 setup actions;
- max 10 entities per action;
- name <=64 code units;
- whole-recipe passability preflight happens before the first setup command;
- canonical serialization is stable while preserving explicit setup order;
- duplicate materializations are byte-identical.

The materializer reuses the shipped deterministic world creation path and authoritative commands. It does not push entities/events directly or create a parallel world model.

### Scenario Setup workspace

Phaser exposes a compact **＋ Scenario** workflow:
- entering Setup rematerializes the selected seed/preset ready base and pauses it;
- exactly Human · Grazer · Wolf are available as setup placements;
- map clicks reuse the existing Phaser pointer→tile→`scene.useTool` path;
- a successful placement is appended to the Recipe only after the authoritative command succeeds;
- impassable placement changes neither Recipe nor command/event/entity identity;
- the workspace shows name, `N/32 actions`, a bounded recent-action summary, Clear and Run;
- Clear rematerializes instead of reversing world arrays;
- Run freezes the normalized Recipe without changing the current start, then ordinary gameplay resumes.

Legacy remains comparison-only and does not become a second Scenario runtime.

### Portable Recipe — Copy Link + JSON Export/Import

A Scenario Recipe can move between browsers without serializing live world state:
- canonical JSON is capped at 8192 UTF-8 bytes;
- the share transport is unpadded base64url under exactly `scenario=`;
- Copy Link uses the current normalized Recipe, never transient world state;
- clipboard failure truthfully exposes the generated link for manual copy;
- Export JSON downloads the exact canonical Recipe string;
- a fresh Phaser `scenario=` URL materializes the Recipe before ordinary startup settles and starts paused;
- visible JSON Import validates and materializes completely before replacing the current world;
- malformed/unsupported/impassable import fails atomically and leaves the current world, Recipe and URL unchanged;
- Legacy reports that Scenario links require Phaser rather than silently pretending to load them.

No local/session/cloud Scenario storage, compression protocol, short-link backend or snapshot export is introduced.

### Replay + Fork

A shared/imported Scenario is reusable:
- **Replay Scenario** means rematerialize the current frozen Recipe and install the exact paused start;
- Replay is not timeline rewind, event replay or snapshot restore;
- stale Event Card, Focused Story, Inspector and selection presentation is cleared after world replacement;
- stable Watchlist refs remain durable and can re-resolve against rebuilt authority;
- **Fork / Edit** rematerializes the exact source start and creates an independent normalized editable Recipe copy;
- the original source Recipe identity is retained separately and remains immutable;
- Fork reuses the same Setup workspace and map input path;
- Run freezes the edited fork; Replay of that fork returns exactly to its own deterministic start.

## Product gates satisfied

### Recipe identity is deterministic

The same normalized Recipe materializes the same authoritative world. Metadata/transport owns no world RNG or history.

### Sharing reproduces authority, not a screenshot

Fresh shared URL and visible JSON import reproduce the same Recipe start through the existing materializer. No hidden live-state snapshot is transported.

### Replay is trustworthy

After ordinary simulation and destructive intervention, Replay rebuilds the exact Recipe start instead of trying to reverse later events.

### Fork preserves source identity

Fork creates an independent editable Recipe and deterministic new start while the imported/shared source Recipe remains unchanged.

### The whole loop is usable in the real browser

The canonical full Chromium gate starts from the ordinary product UI, crosses a genuinely fresh shared browser profile, then completes Replay and Fork through visible controls. Manual review confirms the map remains the primary surface.

## Known limits / deliberate non-goals

v0.7 deliberately stops before a general world editor:
- no terrain/elevation/moisture/biome/water/resource painter;
- no arbitrary tile editing;
- no player-facing live snapshot savegame UI;
- no Setup undo/remove-action stack;
- no timeline rewind/event-replay engine;
- no rules DSL, scripting/mod execution, objectives, quests or scoring;
- no cloud accounts, sync, workshop/discovery backend, ratings or comments;
- no QR/short-link service or compression protocol;
- no custom map-size contract;
- no new ecology/civilization simulation mechanics;
- no AI-generated canonical Scenario authority;
- no generic conversion of every God Power into a Recipe action.

Terrain editing belongs to a later bounded stage only after an authoritative terrain-mutation contract exists.
