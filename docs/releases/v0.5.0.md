# WorldBoxSR v0.5.0 — World Stories

v0.5.0 strengthens a different part of the god-game fantasy: **this world has a history I can follow, revisit and remember.**

The release turns the existing bounded authoritative event history into a compact game-facing memory layer. It does not add a second narrative truth system. Event Cards, story trails, Watchlist and Chronicle lenses all read recorded world facts and stable references; they do not invent motives, hidden causes or replacement state.

## Shipped

### Causal Event Cards

Selecting a retained Chronicle event opens a readable card with:

- a player-facing headline and detail;
- year plus event id/type provenance;
- an explicit Subject;
- ordered recorded Causes;
- truthful unavailable states for refs that have expired from bounded history or no longer resolve.

Retained event causes can open another Event Card. Current map-capable human, creature, settlement, polity and warband refs can use the existing map/inspector path. A polity resolves through its current capital when available. Command refs and expired refs remain visible as unavailable rather than being guessed.

### Focused Story Trail

A player can follow an explicit supported stable ref into a bounded short history without changing world authority.

- human, creature, settlement, polity and warband focus use exact retained event references;
- event focus is deliberately one hop: selected event plus direct retained children, not recursive causal expansion;
- trails are chronological oldest → newest;
- the visible trail is capped at 8 events;
- unavailable focused entities retain their identity and may still expose retained explicit history;
- trail rows reopen the same Event Card path;
- Clear removes only presentation focus.

The feature does not infer membership or relationships from current world state merely to make a story look fuller.

### Watchlist

Players can explicitly Pin/Unpin retained events and supported entity refs worth remembering.

- maximum 6 stable refs;
- same-tab `sessionStorage` persistence;
- malformed, duplicate, unsupported and over-cap persisted entries are sanitized;
- every render re-resolves the stable ref against current authoritative history/entities;
- removed entities or evicted retained events can remain pinned but are shown truthfully unavailable;
- Open, Show on map and Follow story reuse the existing navigation paths;
- Clear all removes presentation memory only.

Watchlist is player memory, not canonical world importance. It is not cloud or cross-device memory and never enters world snapshots/history.

### Chronicle story lenses

Chronicle now exposes exactly four compact game-facing lenses:

- **Highlights** — the existing representative civilization-history policy, unchanged;
- **Recent** — newest retained readable World Story events;
- **Conflict** — explicit war, peace, warband, conquest and rebellion story types;
- **Rule** — explicit polity founding/dissolution and ruler-transition story types.

Every lens is capped at 7 rows. Empty lenses remain honestly empty instead of backfilling unrelated events. Lens selection is presentation-only, is not persisted, and keeps the existing `data-event-id` Event Card path.

There is no relevance score, query language, analytics dashboard or AI ranking behind these lenses.

## Canonical v0.5 gate

The final release gate proves that the four story surfaces work together in one real browser session rather than only as isolated tests.

On deterministic seed45, the production-build Chromium gate uses ordinary shipped gameplay:

1. real Lightning strikes Lindenvale Dominion ruler **Human #23**;
2. authority records `god.lightning` **#172** and `human.died` **#173**;
3. normal deterministic simulation records `polity.ruler_succeeded` **#178**, naming **Human #29** as successor and retaining Event #173 as an explicit cause;
4. the world is paused and its serialized post-succession state becomes the read-only baseline;
5. Chronicle opens Event #178: `Lindenvale Dominion has a new ruler` / `Human #29 succeeds Human #23 after death`;
6. the card exposes Lindenvale Dominion as Subject and retained Event #173 plus Human #29 as recorded Causes;
7. the browser opens Cause Event #173;
8. Show on map resolves polity #3 to current capital **Lindenvale**, with inspector focus at `15,12`;
9. Watchlist Pins exactly `event:178` + `polity:3`;
10. Follow story on polity #3 recovers chronological retained trail `[122,123,124,125,127,128,130,131]` and opens Event #123;
11. the same paused session round-trips Recent `[178,163,162,159,158,157,156]`, Conflict `[134,120,119,117,115,114,111]`, Rule `[178,163,162,159,158,157,156]`, then restores exact Highlights `[178,135,134,120,119,117,115]`;
12. Event Card, Focused Story and Watchlist remain intact throughout the lens round-trip;
13. no raw engine JSON appears;
14. every read-only story/navigation action after the post-succession baseline leaves the authoritative world fingerprint and paused state unchanged.

The canonical helper itself is time-bounded so a Chrome/CDP stall becomes a finite failed gate with diagnostic evidence rather than silently consuming the full CI timeout.

## Product gates satisfied

### Recorded truth remains authoritative

World Stories projects existing `world.history`, event `subject` / `causes` and explicit stable domain IDs. Presentation state does not become a second world model.

### A player can understand a meaningful event

The Event Card gives readable what/when/provenance plus recorded participants and causes without requiring raw event JSON.

### A player can move from history back into the world

Current explicit references can reuse the existing map/inspector path, while unresolved references stay visibly unresolved.

### A player can recover a short coherent story

Focused Story Trail exposes exact retained history for one explicit focus with a deliberate bounded shape rather than an unbounded graph traversal.

### A player can remember what matters to them

Watchlist keeps explicit stable refs within the browser tab/session without changing simulation importance or canonical history.

### A player can browse history without losing context

Highlights/Recent/Conflict/Rule offer small navigation choices while an open Event Card, focus and Watchlist remain usable.

### Read-only story interaction stays read-only

Deterministic unit/runtime tests and real Chromium gates repeatedly compare serialized authoritative world state and prove story navigation does not consume RNG or mutate simulation authority.

## Known limits / deliberate non-goals

v0.5 deliberately stops at a compact deterministic story layer.

- no full replay/rewind engine;
- no graph database or generalized knowledge system;
- no semantic search/query language;
- no relevance scoring or analytics dashboard;
- no AI-authored canonical facts, motives or inferred causal links;
- no required AI summary feature;
- no cloud/cross-device Watchlist sync;
- no promise that bounded history keeps every old event/entity reference forever;
- no new god-power breadth beyond v0.4;
- no economy, trade, religion, technology or renewed civilization-depth expansion;
- no ecology/species research in this release.

Unresolved refs are an expected consequence of bounded history and changing world state. The UI reports that truth instead of synthesizing a replacement explanation.

## What comes next

### v0.6 — Living Ecology

The next product-development stage returns to visible environmental and animal-life systems: supported natural-fauna presets, multiple species, biome affinity/migration, predation/food-web foundations, deterministic initialization and ecology observability. Coherent extinction remains allowed; there is still no hidden survival controller.

v0.5 World Stories is frozen at this release boundary. Do not reopen it during the release handoff merely to add narrative breadth.

The project north star remains: **a living pixel god sandbox where worlds visibly grow, collapse, and remember why.**
