# WorldBoxSR v0.9.0 — World Feel & Public Alpha Polish

v0.9.0 is a deliberate world-first product pass. It does not add a new civilization rules framework; it makes the existing deterministic world substantially easier to see, read, operate and recover.

> **Opening WorldBoxSR feels like looking at a living god-game world first: larger, more readable, visibly changing, recoverable, and usable across desktop and touch.**

## Play online

`https://biandeshen.github.io/WorldBoxSR/play/`

Canonical release QA: `docs/demos/v0.9.0.md`.

## World-first presentation

### The world now dominates desktop play

The Phaser camera no longer reserves exclusive desktop rectangles for HUD panels that already float above the game. The same authoritative world renders beneath the overlay UI.

At the canonical 1440×900 / 24×24 / 28px-tile surface, the default rendered world grows from roughly 718×718 to 864×864: about +20% linear size and +45% rendered map area. Compact/mobile fitting remains separate and bounded.

### Settlement growth is visible without reading numbers

Existing settlement population and capital facts now drive a stronger presentation hierarchy:
- small settlements remain compact;
- larger populations gain wider building, street and field footprints;
- capitals receive stronger civic/flag emphasis;
- no new city-level, economy or building simulation is introduced.

### Polity territory reads from the map

Existing ownership becomes easier to follow through stronger low-alpha washes, dark understrokes, polity-colored borders and inner accents. The world remains a terrain view rather than switching to a separate political-map authority.

## A world that visibly lives

Humans, Grazers and Wolves now use bounded presentation-only gait poses derived from existing movement interpolation. Active settlements receive subtle banner movement and inhabited-hearth ambience. No walking/action state, fuel, production or second animation authority is stored in the simulation.

## Civilization change is easier to understand

v0.9 projects already-authoritative civilization facts directly into the world:
- warband `strength` becomes compact 1–5-soldier formations while the exact number remains visible;
- marching warbands show short objective-direction cues and target-settlement reticles from existing `targetSettlementId` — not fake pathfinding lines;
- recent recorded `warband.engaged` events leave subtle historical battle-site traces without implying terrain damage;
- abandoned settlements render as neutral ruins using real `abandonedDay`, without inventing their former population size;
- conquest occupation and recent rebellion use existing political-history fields for compact identity cues, without adding loyalty, unrest or resistance mechanics.

## God interventions leave truthful world memory

Meteor already had strong instantaneous effects and authoritative vegetation removal. v0.9 adds a subtle recent impact-site memory derived from the recorded Meteor footprint and the **current real vegetation recovery ratio**. When Rain restores the affected vegetation to capacity, the marker disappears naturally.

The marker is not a crater, fire or elevation change; v0.9 does not invent those terrain states.

## Public-alpha persistence

Ordinary Sandbox and Living Ecology worlds now have one browser-local save slot backed directly by the existing engine snapshot format.

- first checkpoint comes from **Save now** or the 30-second autosave;
- after a checkpoint exists, page-hide/hidden-tab lifecycle performs a final flush;
- valid saves restore automatically on a later ordinary launch and install **paused**;
- manual Save / Restore / Clear lives in the compact Inspector `Session` section;
- corrupt, unsupported or quota-failed saves never replace the current world;
- the local envelope contains only `formatVersion`, `savedAt`, `preset` and the existing `snapshotWorld(world)` result.

Scenario worlds remain separate: Scenario Recipe / Replay / Fork continue to own Scenario identity, and active/shared Scenario worlds do not use the ordinary local-world slot.

No engine snapshot-version change is introduced by v0.9.

## Touch and small-screen play

The 430px mobile HUD was compacted so core controls remain reachable without a horizontally overflowing desktop toolbar.

Production Phaser touch semantics are now:
- **tap** — use the selected God Power or Scenario placement;
- **hold (~460 ms)** — inspect without firing a power;
- **drag** — pan;
- **two-finger pinch** — zoom within the same `0.55–2.6` camera limits as desktop wheel zoom.

Real mobile Chromium evidence proves short tap, long-hold Inspector and two-finger pinch on the production path. The final pinch gate records zoom `0.5863× → 1.2703×` with midpoint drift of only `0.00000854` world pixels; authority remains unchanged during/after pinch and a fresh one-finger tap works normally after both fingers release.

## Recovery and accessibility

### Renderer failure recovery

A Phaser renderer startup failure now exposes explicit recovery actions rather than leaving a dead surface or silently switching worlds. The player can retry or choose the compatibility renderer through an intentional recovery path.

### Local accessibility preferences

WorldBoxSR now exposes compact local controls for:
- **Reduce Motion** — monotonically reduces presentation motion and never overrides a stricter system reduced-motion preference;
- **Mute Sound** — suppresses God Power audio before AudioContext creation.

These are presentation preferences only and never change simulation authority.

## Performance and development throughput

The stable Phaser runtime is isolated into a dedicated vendor chunk, while the fast-changing WorldBoxSR application chunk has a checked minified budget below 300 KB. This improves cacheability without changing world behavior.

Pull requests now use a bounded real-Chromium smoke suite for fast iteration, while `main` and release boundaries retain the full v0.4–v0.8 historical browser denominator plus current v0.9 mobile/recovery checks.

## Compatibility and authority note

v0.9 is primarily presentation, input and public-alpha reliability work. It does **not** intentionally change the authoritative simulation rules or engine snapshot schema from v0.8. The single local save slot stores the existing engine snapshot rather than creating a second world format.

Published v0.8 release identities remain immutable.

## Deliberate non-goals

v0.9 does **not** add:
- economy/trade/storage/currency;
- religion/culture/technology;
- new diplomacy or war-resolution rules;
- new conquest, destruction, rebuilding or loyalty simulation;
- marriage/household/claim systems beyond v0.8's shipped scope;
- boats/naval warfare;
- a second mobile renderer or camera/world authority;
- cloud save or multiple local save slots;
- fake pathfinding, crater, fire, industrial or historical-size facts in presentation.
