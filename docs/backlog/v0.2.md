# v0.2 backlog — Playable World

v0.2 is the first executable slice of the master blueprint. It exists to turn the public Pages build from a developer visualization into a coherent god-game experience **without rewriting the deterministic simulation core**.

Technical direction is decided by `docs/decisions/0003-presentation-stack.md`: Phaser 4 presentation + Vite 8 browser build over the existing JS engine.

## Release promise

> Open the public demo and immediately see a living pixel world, understand the god controls, watch a visible change happen, and enjoy using at least the core powers.

## Mandatory product gates

### 5-second gate

A first-time viewer, without documentation, can identify:

- terrain/water/vegetation structure;
- living units;
- settlement presence;
- pause/speed;
- god-power controls.

### 30-second gate

Within 30 seconds of opening the canonical showcase scenario (or using the obvious speed control), a player witnesses a legible change/event.

### Screenshot gate

Every visual/game-feel PR carries before/after evidence in the PR/issue. A PR with only test output does not satisfy this gate.

### Interaction gate

A first-time player can select and use the core powers without reading the README.

### Determinism gate

- full existing tests green;
- save/load continuation green;
- presentation interpolation/effects never mutate authoritative state except through commands;
- headless CLI and Simulation Lab remain usable.

### Delivery gate

- Vite production build deploys through GitHub Pages;
- public Pages demo is the same product path reviewed in development;
- no local-only asset/config dependency.

## Priority constraints until release

- **No new non-correctness ecology research.**
- No compact-grazer persistence/initializer tuning.
- No new abstract analysis subsystem unless it directly supports player-visible UI/chronicle work in this version.
- No infrastructure work unless it blocks the presentation loop, product evidence, CI or Pages.
- No kingdom/diplomacy/war scope creep; v0.3 owns that capability.
- Prefer mature framework/asset primitives over custom low-level plumbing when they deliver equivalent maintainability faster.
- Do not redesign the deterministic simulation solely to make Phaser integration aesthetically cleaner.

## Explicit non-goals

- matching WorldBox feature breadth;
- full civilizations/war;
- predators or food webs;
- universal natural fauna;
- trade/economy/culture/religion;
- world-builder/editor;
- replay/rewind;
- final bespoke production art for every asset;
- mobile release commitment.

## Release review question

Before tagging v0.2, ignore commit count and test count for one review pass and answer only:

> If someone opens `https://biandeshen.github.io/WorldBoxSR/` with no project context, does this now feel like the beginning of a game worth watching and touching?

If the answer is no, v0.2 is not complete.
