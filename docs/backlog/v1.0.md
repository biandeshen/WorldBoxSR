## Capability 2 — Certified Runtime & Recovery Envelope — COMPLETE

**Goal:** state and enforce only the public runtime surfaces WorldBoxSR actually certifies.

Canonical support statement: `docs/SUPPORT.md`.

### Certified v1.0 surfaces

1. **Chrome/Chromium-class desktop Phaser · 1440×900** — production Pages/Vite path, `showcase ready`, God Power/story/Scenario interaction and full historical main/release denominator;
2. **Chrome/Chromium-class coarse-touch Phaser · 430×820** — compact HUD, tap tool, hold inspect, drag pan, two-finger pinch with authority-neutral focus preservation and clean one-finger recovery;
3. **Legacy Canvas ordinary-world compatibility fallback** — explicit Retry/Compatibility recovery path, not feature-equivalent Phaser.

Explicit limitations:
- Scenario remains Phaser-only and Legacy fallback consequences must be disclosed;
- Firefox/Gecko, Safari/WebKit and arbitrary other browser/device surfaces remain uncertified/best effort until real gates exist;
- 430×820 is the certified touch QA surface, not a universal mobile guarantee;
- no cloud/cross-device save;
- the public 24×24 showcase is the initial v1.0 product performance envelope;
- the 64×64 1k/10k Node benchmark remains diagnostic, not an FPS/tick SLA.

Structural build contract:
- exactly one `phaser-vendor-*.js` chunk;
- exactly one `phaser_main-*.js` app chunk;
- `phaser_main` ≤ 300,000 B minified;
- vendor chunk larger than app chunk.

## Capability 3 — Cross-System Stable Sandbox Gate — NEXT

**Goal:** prove the shipped systems compose as one dependable product, not only as isolated historical feature gates.

This capability owns the v1.0 implementation freeze / canonical release journey and should **reuse existing product evidence wherever possible**.

### Journey A — ordinary world

1. open reproducible seed/preset on production `/play/`;
2. observe ecology + settlement/polity state;
3. perform a real God Power intervention;
4. follow the recorded causal result through Chronicle / Event Card / Inspector;
5. `Save now` to the ordinary local slot;
6. advance or mutate the world;
7. Restore the exact saved authority, installed paused;
8. prove the restored authority is the saved world rather than a new rematerialization and that read-only story/inspection state never changed world truth.

Deterministic save/load continuation remains owned by existing engine/local-save tests plus Capability 1’s compatibility matrix; the browser gate must prove the production UI uses that contract.

### Journey B — Scenario world

Reuse the existing canonical Scenario Builder journey:
1. compose/share exact Scenario Recipe v1;
2. fresh-open the same source;
3. Run and diverge through ordinary gameplay;
4. Replay exact source;
5. Fork and edit;
6. Run/diverge/replay exact fork;
7. prove ordinary local-world persistence stays disabled while Scenario identity is active.

### Acceptance

- [ ] ordinary production browser journey composes causal story navigation with Save → mutate → Restore in one session;
- [ ] Restore returns exact saved authoritative browser world and installs paused;
- [ ] active Scenario visibly disables ordinary local-world persistence and keeps Recipe / Replay / Fork as the identity contract;
- [ ] existing canonical Scenario Builder evidence remains exact;
- [ ] one small v1.0 verifier composes ordinary-world evidence + canonical Scenario evidence rather than reimplementing every old gate;
- [ ] authority snapshots/RNG remain exact at read-only boundaries;
- [ ] v0.4–v0.9 historical browser regressions remain green;
- [ ] no new simulation, save format, Scenario format or product feature is added.
