# v1.0 backlog — Stable Sandbox Identity

Planning gate: #313.

Primary promise:

> **WorldBoxSR behaves like one dependable sandbox product: reproducible worlds, stable browser play, recoverable saves, understandable history, supported public surfaces, and coherent creation/intervention/civilization/ecology/story workflows.**

**Status: ACTIVE — Capability 1 COMPLETE; Capability 2 NEXT.** This is a finite three-capability stage. Do not add breadth merely because the version number is 1.0.

## Audited starting point

### Portable state

- current engine snapshot schema is `SNAPSHOT_VERSION = 16`;
- v1.0 now exports the frozen engine support baseline `SUPPORTED_SNAPSHOT_VERSIONS = [10,11,12,13,14,15,16]`;
- ordinary browser local-save envelope is `worldboxsr:local-world:v1` / `formatVersion: 1` and embeds the engine snapshot;
- Scenario Recipe is strict `kind=worldboxsr-scenario`, `version: 1`, canonical JSON with whole-recipe preflight.

Historical provenance remains explicit:
- public v0.3.0 / v0.4.0 / v0.7.0 used engine snapshot v15;
- public v0.8.0 / v0.9.0 use engine snapshot v16;
- v10–v14 are older accepted prototype/internal schemas, not falsely described as tagged release artifacts.

### Certified runtime today

- browser QA is Chrome/Chromium based;
- canonical desktop evidence is 1440×900 production Phaser;
- canonical coarse-touch evidence is 430×820 production Phaser;
- Legacy renderer is an explicit compatibility path for ordinary worlds;
- Scenario links require Phaser and compatibility fallback explicitly drops Scenario state rather than faking support;
- Firefox/Safari are not currently real-browser gated.

### Performance today

- `phaser_main` has an existing hard `300,000 B` minified CI budget and dedicated Phaser vendor split;
- `npm run bench` measures 64×64 worlds at 1k/10k starting population, but is diagnostic only: no calibrated non-flaky CI threshold exists.

### Discoverability today

- desktop Power Dock exposes Click / Shift-click / Drag / Wheel / Alt-click;
- Scenario Setup has its own placement/navigation hint;
- mobile exposes Tap / Hold / Drag / Pinch and keeps core Pause/View/World controls reachable;
- Session, Accessibility and renderer recovery actions are already explicit in-product.

### Extension surface today

`content/` is still a future-facing placeholder rather than a real public plugin contract. v1.0 will not manufacture a mod API just to call the product stable.

## Capability 1 — Portable Compatibility Contract — COMPLETE

**Goal:** turn existing migration capability into an explicit, regression-proof support promise.

### Support baseline

- historical engine snapshots **v10–v16** are mandatory supported inputs for v1.0;
- if a later v1.0 implementation increments the current snapshot version, v10–v16 remain mandatory historical inputs and each new current version joins the matrix;
- local-world envelope **v1** remains supported and may embed any engine snapshot version supported by `worldFromSnapshot()`;
- Scenario Recipe **v1** remains supported and canonical;
- unsupported/corrupt/future versions fail explicitly and atomically without replacing the running world.

### Acceptance

- [x] one explicit independently named compatibility case for each engine snapshot version v10–v16;
- [x] every historical case loads and normalizes to the current v16 schema;
- [x] after a fixed 12-tick deterministic continuation horizon, migrated authority matches a current-schema normalized equivalent;
- [x] local-save envelope v1 can wrap/restore every supported historical engine case;
- [x] local-save future envelope / unsupported embedded snapshot rejection is explicit and yields no replacement world;
- [x] Scenario Recipe v1 remains canonical and accepted;
- [x] unsupported future Scenario Recipe version remains an explicit rejection rather than guessed migration;
- [x] support metadata is centralized as exported frozen `SUPPORTED_SNAPSHOT_VERSIONS`, so adding a future current version cannot silently erase the historical baseline.

## Capability 2 — Certified Runtime & Recovery Envelope — NEXT

**Goal:** state and enforce the public surfaces WorldBoxSR actually supports instead of vaguely claiming every browser/device.

### Initial certified v1.0 surfaces

1. current stable Chrome/Chromium-class desktop, production Phaser, canonical **1440×900** surface;
2. Chrome/Chromium-class coarse touch, production Phaser, canonical **430×820** surface;
3. existing Legacy renderer as explicit compatibility fallback for ordinary worlds.

Scenario remains Phaser-only. Compatibility fallback may drop Scenario only through the existing explicit disclosure.

Firefox/Safari remain **best effort / uncertified** until a later bounded slice adds real browser evidence. Do not claim support without a gate.

### Acceptance

- [ ] public production `/play/` build reaches `showcase ready` on both certified Phaser surfaces;
- [ ] desktop power/camera/inspect affordance text is visible and truthful at 1440×900;
- [ ] mobile Pause/View/World and Tap/Hold/Drag/Pinch contract remain reachable/truthful at 430×820;
- [ ] short tap, long hold, pan/pinch suppression and post-pinch one-finger recovery stay authority-correct;
- [ ] renderer fault injection still exposes explicit Retry + compatibility behavior;
- [ ] Scenario→Legacy consequence remains disclosed and cannot silently install a different authoritative Scenario;
- [ ] `phaser_main` remains ≤ `300,000 B` minified with exactly one dedicated Phaser vendor chunk;
- [ ] certified-support statement is visible in project/release docs;
- [ ] no uncalibrated 1k/10k wall-clock SLA is promoted to a release blocker.

### Performance policy

The public **24×24** shipped showcase surfaces are the initial v1.0 performance/support contract. The 64×64 1k/10k Node benchmark remains diagnostic until calibration proves a meaningful runner-independent threshold.

## Capability 3 — Cross-System Stable Sandbox Gate

**Goal:** prove the shipped systems compose as one dependable product, not only as isolated historical feature gates.

This capability owns the v1.0 canonical release journey and should reuse existing product surfaces.

### Journey A — ordinary world

1. open reproducible seed/preset on production `/play/`;
2. observe ecology + settlement/polity state;
3. use a God Power intervention with existing causal event/history projection;
4. follow the result through Inspector / World Stories;
5. `Save now` to ordinary local slot;
6. advance or mutate the world;
7. Restore the exact saved authority, installed paused;
8. continue both original saved state and restored state through a fixed horizon and require deterministic agreement.

### Journey B — Scenario world

1. compose or import canonical Scenario Recipe v1;
2. Run the Scenario;
3. observe/intervene using ordinary shipped surfaces;
4. Replay exact source;
5. Fork to editable copy;
6. verify ordinary local-world autosave/restore never overrides active/shared Scenario identity.

### Acceptance

- [ ] both journeys run against production-built surfaces, not test-only UIs;
- [ ] authority snapshots/RNG remain exact at intended read-only boundaries;
- [ ] save/restore and Replay/Fork use their existing separate identity contracts;
- [ ] causal Inspector/Story facts agree with recorded authority;
- [ ] v0.4–v0.9 historical browser regressions remain green;
- [ ] one bounded v1.0 release gate composes these journeys without duplicating every older gate implementation.

## Explicit decisions / non-goals

### Not a v1.0 capability

- public plugin/mod API or marketplace;
- large tutorial framework absent failed first-session evidence;
- Firefox/Safari support claim without real gates;
- uncalibrated 1k/10k timing SLA;
- economy/trade/currency;
- religion/culture/technology;
- naval warfare;
- professions/classes;
- marriage/households;
- configurable succession systems;
- broad diplomacy rewrite;
- multiplayer/cloud sync;
- procedural AI-authored history;
- new renderer.

### Stable external/portable contracts intended for v1.0

- engine snapshot support baseline v10–v16 (and any later current v1.0 schema added without dropping that floor);
- ordinary local-save envelope v1;
- Scenario Recipe v1;
- public certified browser/touch/recovery behavior documented above.

Internal content/model APIs remain free to evolve under tests and authority invariants until a real extension contract is deliberately designed.

## Execution rules

1. execute capabilities in order unless a real blocker is documented;
2. ordinary slices use focused tests plus the existing relevant browser smoke;
3. full historical/cross-system proof belongs at capability/release boundaries;
4. published v0.9 and older release identities never move;
5. do not open Capability 3 implementation while Capability 2 is incomplete.
