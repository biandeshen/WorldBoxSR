# v0.7 backlog — Scenario Builder & Sharing

Release gate: #240. Version promise: **I can assemble a world setup, share/import its compact deterministic Scenario Recipe, and reopen exactly the same starting world before running, replaying or forking a different history.**

v0.7 productizes existing deterministic startup + commands. It is **not** the full terrain/world editor.

## Binding architecture facts

- engine snapshots already provide exact internal save/load continuation, but the browser has no player-facing live-world save/import/export/share workflow;
- current product startup is deterministic 24×24, seed + `Sandbox | Living Ecology`, followed by the existing 40-year showcase warmup;
- authoritative creation commands already exist for Human, Grazer and Wolf;
- Scenario Recipe v1 and visible Scenario Setup are now merged product capabilities;
- `scenario=` is the one portable Recipe transport query key; it is distinct from existing `renderer=` selection;
- there is no authoritative terrain/biome mutation command today, so tile painting remains deliberately deferred rather than implemented as presentation-owned state.

## Frozen recipe scope

A v0.7 Scenario Recipe is a **versioned startup input, not a world snapshot**.

Required logical shape:

```json
{
  "kind": "worldboxsr-scenario",
  "version": 1,
  "name": "My scenario",
  "base": {
    "seed": 45,
    "preset": "sandbox"
  },
  "setup": [
    { "type": "spawn_human", "x": 8, "y": 8, "count": 1 },
    { "type": "spawn_creature", "species": "grazer", "x": 9, "y": 8, "count": 1 }
  ]
}
```

Exact internal helper names may differ, but release scope may not widen silently.

### Base semantics

- exactly current `sandbox | living_ecology` presets;
- exactly current supported 24×24 product world;
- exactly current 40-year showcase-ready materialization before setup actions;
- no recipe present = byte-compatible v0.6 startup behavior;
- blank/day0/custom-size worlds are not required in v0.7.

### Setup actions

Exactly three placement identities:
- Human;
- Grazer;
- Wolf.

All placements must go through existing authoritative command paths. Wolf may be visible in Scenario Setup without becoming a new ordinary God Power.

Bounds:
- max 32 setup actions;
- max 10 entities per placement action;
- coordinates must be current-world integer tiles and must satisfy existing passability validation;
- name is bounded presentation metadata and never enters authoritative world snapshots;
- unknown kind/version/preset/action/species or malformed data fails explicitly;
- portable canonical JSON is capped at 8192 UTF-8 bytes and encoded as unpadded base64url for `scenario=`.

The order of `setup` is authoritative recipe input and must be preserved exactly.

## Truth boundaries

- Engine remains the only world truth.
- Recipe is deterministic input to world creation/commands, never a live-state mirror.
- Recipe metadata/transport never enters `snapshotWorld`, `world.history` or RNG.
- Successful setup placements are authoritative commands; failed actions are not recorded in recipe.
- Setup actions cannot continue after `Run Scenario` unless the player explicitly Replay/Forks back into Setup.
- Existing v0.6 startup with no recipe is a regression contract.
- Phaser is the v0.7 product surface; Legacy remains comparison compatibility only.

## Non-goals / stop rules

- No terrain/elevation/moisture/biome/water painter.
- No arbitrary tile/resource editor.
- No full player-facing live snapshot save-game UI.
- No arbitrary config/rules DSL or scripting/mod execution.
- No objectives, quests, victory/defeat or scoring.
- No cloud sync, accounts, workshop/discovery backend, ratings or comments.
- No AI-generated scenario authority.
- No new simulation/ecology/civilization mechanics.
- No generic conversion of every God Power into setup actions.
- No custom map size in the v0.7 release contract.
- If a requested builder feature requires a new authoritative terrain mutation model, defer it instead of placing that mutation in UI code.

## Product stop rule

A slice enters v0.7 only if it directly improves this loop:

**compose setup → share/import → exact same start → Run → Replay or Fork.**
